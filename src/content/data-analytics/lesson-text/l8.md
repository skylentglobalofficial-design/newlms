# SQL joins and data-quality checks

**Objective:** Detect duplicates, label missing region, and LEFT JOIN to a small calendar so months without a trick still appear.

**Why this matters:** INNER JOIN drops what you cannot match. Missing months look like “zero sales” when they are actually missing keys. Duplicate order IDs inflate counts.

**Prerequisite:** Lesson 7. Same `sales` table.

**Estimated time:** 50 minutes.

**Datasets:** [northwind_sales.csv](/content/data-analytics/northwind_sales.csv), [northwind_hr.csv](/content/data-analytics/northwind_hr.csv) (quality only — do not fake a sales–HR join).

## Explain

**JOIN types (what this course needs)**

| Join | Keeps |
| --- | --- |
| INNER | Rows with a match on **both** sides |
| LEFT | All left rows; right columns NULL if no match |
| RIGHT / FULL | Know they exist; you will not need them on Northwind |

There is only **one fact table** in the sales file. You still join when you create a **dimension** you do not want to lose — for example a calendar of six months.

**Quality checks that are SQL, not vibes**

```sql
-- duplicate keys
SELECT order_id, COUNT(*) AS n
FROM sales
GROUP BY order_id
HAVING COUNT(*) > 1;

-- blank region
SELECT order_id, city, category
FROM sales
WHERE region IS NULL OR trim(region) = '';

-- type / range
SELECT order_id, units, unit_price
FROM sales
WHERE units <= 0 OR unit_price <= 0;
```

Expect: **NW-10013** duplicated; **NW-10024** and **NW-10089** blank region; **NW-10055** and **NW-10122** range failures.

**Label, do not delete, missing region**

```sql
SELECT CASE
         WHEN region IS NULL OR trim(region) = '' THEN 'Unknown'
         ELSE region
       END AS region_std,
       ROUND(SUM(units * unit_price * (1.0 - discount_pct / 100.0)), 0) AS net_revenue
FROM sales
WHERE units > 0 AND unit_price > 0 AND returned = 'no'
GROUP BY 1
ORDER BY net_revenue DESC;
```

Unknown should be about **5988**, not zero.

## Worked example — calendar LEFT JOIN

Create a month list so a future empty month would still show:

```sql
CREATE TABLE month_dim (yyyymm TEXT PRIMARY KEY);

INSERT INTO month_dim (yyyymm) VALUES
  ('2026-01'),('2026-02'),('2026-03'),
  ('2026-04'),('2026-05'),('2026-06'),
  ('2026-07');  -- July is empty on purpose

SELECT m.yyyymm,
       COALESCE(ROUND(SUM(s.units * s.unit_price * (1.0 - s.discount_pct / 100.0)), 0), 0) AS net_revenue
FROM month_dim AS m
LEFT JOIN sales AS s
  ON substr(s.order_date, 1, 7) = m.yyyymm
 AND s.units > 0 AND s.unit_price > 0 AND s.returned = 'no'
GROUP BY m.yyyymm
ORDER BY m.yyyymm;
```

**Join condition in ON vs WHERE:** if you put `s.returned = 'no'` in WHERE after a LEFT JOIN, you turn it into an inner join on matching sales rows and **drop July**. Keep filters on the right table in the ON clause (or filter in a subquery, then LEFT JOIN).

July should appear with **0**. That is the point.

**Do not INNER JOIN sales to HR on region** and call it “workforce caused April”. Many employees share a region; that is not a grain-matched model. In the capstone you analyse HR **beside** sales, not as a proven cause.

HR quality preview (import `hr` the same way):

```sql
SELECT employee_id, department, monthly_salary_inr, performance_rating
FROM hr
WHERE department IS NULL OR trim(department) = ''
   OR performance_rating = 'N/A'
   OR monthly_salary_inr LIKE '%,%';
```

Expect **E-107**, **E-119**, **E-133**.

## Step-by-step procedure

1. Run the three quality queries. Write the IDs in a log.
2. Build `region_std` summary including Unknown.
3. Build `month_dim` including July; LEFT JOIN; confirm July = 0.
4. Optional: `CREATE TABLE category_map (raw TEXT, std TEXT)` and JOIN instead of CASE — same result, easier to audit.

## Common mistakes

- `DELETE FROM sales WHERE region = ''` to “clean”. You just hid ₹6k and two orders.
- WHERE on the right table after LEFT JOIN, losing unmatched months.
- Joining HR to sales on region and presenting a correlation as a cause.
- Treating the duplicate order_id as one order and dropping March revenue.

## Knowledge check

After LEFT JOIN from `month_dim` to `sales`, you add `WHERE returned = 'no'` in the outer query. July disappears. Why?

**Answer:** July has no sales rows, so `returned` is NULL. `NULL = 'no'` is not true, so the WHERE removes the unmatched month. Filter returned in ON or in a subquery.

Mark complete when duplicates, blank region, and a seven-month LEFT JOIN (July = 0) are in your sql file.
