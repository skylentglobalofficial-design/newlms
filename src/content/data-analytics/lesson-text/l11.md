# Measures, dimensions, and calculated fields

**Objective:** Separate dimensions from measures, write calculated fields (spreadsheet or BI), and add margin without lying about returns.

**Why this matters:** Putting a measure on an axis meant for a dimension, or averaging percentages incorrectly, is how dashboards mislead.

**Prerequisite:** Lesson 10 wireframe. Same Northwind working data.

**Estimated time:** 45 minutes.

## Explain

**Dimension** — how you slice: category, region, month, channel, returned flag. Usually text or date. You GROUP BY dimensions.

**Measure** — what you aggregate: net revenue, units, order lines, cost. Usually numeric. You SUM / COUNT / AVERAGE measures.

**Calculated field** — a formula stored in the model so every visual uses the same definition.

| Field | Kind | Formula / rule |
| --- | --- | --- |
| category_std | dimension (calculated) | map Elec. / electronics → Electronics |
| region_std | dimension (calculated) | blank → Unknown |
| net_revenue | measure | units × unit_price × (1 − discount/100) on valid rows |
| cogs | measure | units × cost_per_unit on valid rows |
| gross_margin | measure | net_revenue − cogs |
| margin_pct | measure | gross_margin / net_revenue — **never** average of row-level percents as the company percent |
| mom_pct | measure | change vs prior month; January n/a |

**Invalid aggregation:** `AVERAGE(discount_pct)` is not “the company’s discount”. Weighted discount is `1 − SUM(net_revenue) / SUM(units * unit_price)` on valid rows.

## Worked example — margin on NW-10001

units 1, unit_price 2199, discount 0, cost 1100, returned no.

- net_revenue = 2199
- cogs = 1100
- gross_margin = 1099
- margin_pct = 1099 / 2199 ≈ 50%

Now a discounted coffee line (January NW-10013): units 7, price 449, discount 10%, cost 210.

- net_revenue = 2828.7
- cogs = 1470
- gross_margin = 1358.7
- margin_pct ≈ 48%

**Returns:** a `returned = yes` row is **not** negative margin in the headline unless operations says refunds are stored that way. In this extract, returns are excluded from net_revenue. You may add a **separate** measure `returned_units` for operations.

Sheets calculated columns (continuing lesson 4 helpers):

```
P2 cogs:          =IF(N2, G2*J2, 0)
Q2 gross_margin:  =O2-P2
```

Pivot: SUM of `gross_margin` by `category_std`.

Power BI-style measure (if you use Desktop) — conceptual DAX, optional:

```
Valid Net Revenue =
SUMX(
  FILTER(sales, sales[units] > 0 && sales[unit_price] > 0 && sales[returned] = "no"),
  sales[units] * sales[unit_price] * (1 - sales[discount_pct] / 100)
)
```

You do not need DAX to finish this course. A spreadsheet measure table is enough.

## Step-by-step procedure

1. Add `cogs` and `gross_margin` on valid rows only.
2. Category pivot: net revenue, cogs, margin, margin %.
3. Compute company margin % as `SUM(margin)/SUM(net_revenue)`, not as `AVERAGE(row margin %)`.
4. Add a **returned_units** measure from rows where returned = yes (do not mix into headline revenue).
5. Update your dashboard: optional fourth KPI = gross margin, still one question.

## Practice

1. Which of these is a dimension: `channel`, `net_revenue`, `mom_pct`?
2. If Electronics margin % is 49% and Grocery is 41%, is company margin the average 45%?
3. Should `returned` be a dashboard filter, a separate page, or both?

## Expected result

1. `channel` is a dimension. The others are measures (mom_pct is a measure derived from a measure).
2. **No.** Company margin is total margin / total revenue (weighted). Equal-weighted 45% is wrong if Electronics is larger.
3. Prefer a filter **and** a note. A lead should be able to isolate returns without polluting the ₹8.12 lakh KPI.

## Common mistakes

- Plotting `discount_pct` as a bar “revenue”.
- Averaging percentages.
- Showing margin on invalid rows (negative units make nonsense COGS).
- Six calculated fields nobody defined in a dictionary.

## Knowledge check

A row has units 2, unit_price 50, discount_pct 10, cost 20, returned no. Gross margin is:

A. 100  
B. 90 − 40 = 50  
C. 10  
D. 20

**Answer:** B. Net revenue = 2×50×0.9 = 90. COGS = 2×20 = 40. Margin = 50.

Mark complete when your model has documented measures for net revenue, cogs, margin, and returned units — and the dashboard still answers one question.
