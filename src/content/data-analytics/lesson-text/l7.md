# SQL SELECT, WHERE, and aggregates

**Objective:** Load Northwind sales into SQLite (or any SQL engine) and write SELECT / WHERE / GROUP BY queries that reproduce the spreadsheet totals.

**Why this matters:** A pivot you cannot re-run is a screenshot. SQL is how finance re-runs June when July lands.

**Prerequisite:** Lessons 1–5 (valid-row rule and net revenue). Tools: [SQLite](https://sqlite.org) CLI, DB Browser for SQLite, or any engine that can import CSV. The LMS does not execute SQL.

**Estimated time:** 50 minutes.

**Dataset:** [northwind_sales.csv](/content/data-analytics/northwind_sales.csv)

## Explain

SQL is a language for asking a table questions.

Core clauses, in the order the engine *thinks* (not the order you type):

1. `FROM` — which table
2. `WHERE` — which **rows** survive
3. `GROUP BY` — how to bucket remaining rows
4. `HAVING` — which **groups** survive
5. `SELECT` — which columns/expressions to return
6. `ORDER BY` — sort the result

Typed order is `SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY`.

**Aggregation** needs `GROUP BY` for every non-aggregated selected column.

Net revenue expression (SQLite):

```sql
units * unit_price * (1.0 - discount_pct / 100.0)
```

Use `1.0` so integer division does not floor discounts to zero.

## Worked example — import and first queries

Create a database and import (SQLite CLI):

```sql
.mode csv
.headers on
.import northwind_sales.csv sales
```

If the header becomes a data row, delete it (`DELETE FROM sales WHERE order_id = 'order_id';`).

Sanity:

```sql
SELECT COUNT(*) AS row_count,
       COUNT(DISTINCT order_id) AS distinct_orders
FROM sales;
```

Expect **180** and **179**. That gap *is* the duplicate NW-10013.

Valid net revenue overall:

```sql
SELECT ROUND(SUM(units * unit_price * (1.0 - discount_pct / 100.0)), 2) AS net_revenue,
       COUNT(*) AS valid_rows
FROM sales
WHERE units > 0
  AND unit_price > 0
  AND returned = 'no';
```

Expect **166** valid rows and about **812019.55**.

By mapped category:

```sql
SELECT CASE
         WHEN lower(trim(category)) IN ('elec.', 'electronics') THEN 'Electronics'
         ELSE trim(category)
       END AS category_std,
       ROUND(SUM(units * unit_price * (1.0 - discount_pct / 100.0)), 0) AS net_revenue
FROM sales
WHERE units > 0 AND unit_price > 0 AND returned = 'no'
GROUP BY 1
ORDER BY net_revenue DESC;
```

Electronics should lead (~347k).

**WHERE vs HAVING**

```sql
-- rows: only non-returned
WHERE returned = 'no'

-- groups: categories with more than 10 valid units
HAVING SUM(units) > 10
```

You cannot put `SUM(units) > 10` in WHERE. WHERE does not see aggregates.

## Step-by-step procedure

1. Import CSV → table `sales`.
2. Run COUNT(*) vs COUNT(DISTINCT order_id).
3. Run the valid-row net revenue query. Match the spreadsheet from lesson 4 within rounding.
4. Run category GROUP BY with the CASE alias map.
5. Run monthly:

```sql
SELECT substr(order_date, 1, 7) AS yyyymm,
       ROUND(SUM(units * unit_price * (1.0 - discount_pct / 100.0)), 0) AS net_revenue
FROM sales
WHERE units > 0 AND unit_price > 0 AND returned = 'no'
GROUP BY 1
ORDER BY 1;
```

6. Save queries in a file `northwind_l7.sql`. You will paste them again in assignment l13.

## Common mistakes

- `SELECT category, SUM(...)` without GROUP BY (engine error, or worse, silent wrong row in some tools).
- Integer math: `discount_pct / 100` → 0 in some engines. Use `100.0`.
- Filtering `returned = 'no'` in one query and forgetting it in the next, then comparing totals.
- `SELECT *` as “the analysis”.

## Knowledge check

You need categories with valid net revenue above ₹150,000. Which clause filters those groups?

A. WHERE SUM(net) > 150000  
B. HAVING SUM(units * unit_price * (1.0 - discount_pct/100.0)) > 150000  
C. ORDER BY 150000  
D. JOIN

**Answer:** B. Aggregates belong in HAVING (or a subquery).
