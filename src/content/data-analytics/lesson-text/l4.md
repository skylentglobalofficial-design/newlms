# Spreadsheet tables, types, and filters

**Objective:** Import Northwind sales into Sheets or Excel, lock types, and filter to valid rows without destroying the raw extract.

**Why this matters:** Most “wrong dashboard” disasters start as a column that looks numeric but is not, or a filter that silently drops the blank region.

**Prerequisite:** Lessons 1–2. Tools: Google Sheets or Excel. The LMS does not run a spreadsheet for you.

**Estimated time:** 45 minutes.

**Dataset:** [northwind_sales.csv](/content/data-analytics/northwind_sales.csv)

## Explain

A spreadsheet is a table: **rows are observations**, **columns are fields**. Analysis goes wrong when:

- A number is stored as text (`"46,250"` in the HR file — you will meet it in the capstone).
- A category has aliases (`Electronics` / `Elec.` / `electronics`).
- Filters hide blanks, so you think you have no Unknown region.

**Types in this file**

| Column | Sensible type | Trap |
| --- | --- | --- |
| order_id | text | Looks like an ID; it is **not** unique |
| order_date | date | Keep as date so you can group by month |
| region, city, category, product, channel, returned | text | Blanks in region |
| units, unit_price, discount_pct, cost_per_unit | number | Negative units; zero price |

**Filters vs deleting rows:** Filter to inspect. Copy valid rows to a **working** tab. Leave Raw untouched.

## Worked example — types and a helper column

1. File → Import the CSV (Sheets: File → Import → Upload). Choose “comma” and “header row”.
2. Rename the tab `raw_sales`. Duplicate it to `work`.
3. After import, file order is: A `order_id` … E `category` … G `units`, H `unit_price`, I `discount_pct`, K `returned`, L `channel`. Add helper columns at the **end** so letters do not shift.

4. Column M `category_std`:

`=IFS(OR(LOWER(TRIM(E2))="elec.", LOWER(TRIM(E2))="electronics"), "Electronics", TRUE, TRIM(E2))`

5. Column N `valid_flag`:

`=AND(G2>0, H2>0, LOWER(K2)="no")`

6. Column O `net_revenue`:

`=IF(N2, G2*H2*(1-I2/100), 0)`

Invalid rows contribute **0** to the headline, not a blank that breaks SUM.

7. Freeze row 1. Turn on filters.

Filter `valid_flag` = FALSE. You should see the 14 excluded rows, including NW-10055 and NW-10122 and the twelve `returned = yes` lines.

Filter `region` to **blanks**. You should see NW-10024 and NW-10089. **Do not delete them.** You will label them Unknown in the next lesson.

## Step-by-step procedure

1. Import → `raw_sales` + `work`.
2. Confirm 180 data rows (`=COUNTA(A:A)-1` on raw).
3. Add `category_std`, `valid_flag`, `net_revenue`.
4. `=SUM(net_revenue)` on work. Expect **about 812020**.
5. `=COUNTIF(valid_flag, TRUE)` → 166.
6. Document every helper in a `data_dictionary` tab: column name, formula, why.

## Practice

1. Find all unique `category` values (Data → unique / pivot / `=UNIQUE`). List them.
2. Count distinct `order_id` vs 180 rows. What is the difference?
3. Filter `channel` to online and sum valid net revenue. Store vs online: which is larger in this extract?

## Expected result

1. At least `Electronics`, `Elec.`, `electronics`, `Apparel`, `Home`, `Grocery` (Home may appear as `Home` in the file). Aliases must be visible before you map them.
2. Distinct order_id is **179** because **NW-10013** is duplicated. `COUNTA` of rows is 180.
3. Valid net revenue is larger in **store** (≈ ₹5.34 lakh) than **online** (≈ ₹2.78 lakh). Your rounding may differ.

## Common mistakes

- Importing with the wrong delimiter so category and units shift columns.
- Typing over raw values instead of helper columns.
- Filtering away blanks and then wondering where Unknown revenue went.
- Using `valid_flag` as text `"TRUE"` that COUNTIF misses.

## Knowledge check

You SUM `unit_price` on filtered valid rows and get a number much smaller than ₹8.12 lakh. What did you measure?

**Answer:** The sum of list prices on those rows — not revenue. Revenue needs units and discount. A “close” number is still the wrong metric.

Mark complete when your work tab has helper columns, 166 valid rows, and a SUM near ₹812,020 without editing `raw_sales`.
